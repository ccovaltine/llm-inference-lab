IO-AWARE EXACT ATTENTION · 写给已经看懂 KV CACHE 的你

FlashAttention：
注意力矩阵，不必落地

你已经知道，KV Cache 把历史 K／V 留在显存里，用空间换时间。但注意力还有另一半代价：每个 token 的 Q 都要和历史 K 算出一个 N×N 的分数矩阵。朴素实现会把它整块写进 HBM、读回来做 softmax、再写回去——FlashAttention 的全部思想，就是让这张矩阵从不离开片上 SRAM。数学不变，字节的路变了。

① HEAD-TO-HEAD / 同一个例子，两条路并排跑

4 个 token、16 个分数：一边三进三出 HBM，一边零落盘

N = 4 · d = 2 · 块 = 2 · FP16 · 确定性数值

同一个固定的小例子（Q、K、V 数值全程可手算复现），两条路上下并排执行。上：标准注意力——S、P 两张 4×4 矩阵各自写回 HBM 再读回；下：FlashAttention——分块进 SRAM，用 m／ℓ／O 三个流动变量在线合并。两条车道各有独立的步骤控制，可以按不同节奏对照推进；盯住底部的字节计数器：两边算出的 O 逐位相同，HBM 流量却差一倍——而这只是 N=4 的教学尺寸，差距随 N² 拉大。

② THE BOTTLENECK / 瓶颈在带宽，不在算力

同一张 N×N 矩阵，要在 HBM 里走三个来回

单位：FP16 = 2 B / 元素
前情回顾 · 你在 KV Cache 一篇里已经知道解码时每个新 token 的 Q 都会去读全部历史 K／V。那一篇关注「读显存里的缓存」；这一篇关注另一个更隐蔽的成本——QKᵀ 产生的那张 N×N 分数矩阵本身。

标准实现把注意力拆成一串独立的算子：先算 S = QKᵀ/√d 并写回 HBM，再读回 S 做 softmax 得到 P 并写回，最后读回 P 与 V 相乘。S 和 P 各是 N×N——序列 4096 时，单张就是 32 MiB，还要写一遍、读一遍、再写一遍、再读一遍。

关键在于算术强度：注意力的 FLOPs 是 4N²d，而 HBM 读写是 8N²＋8Nd 字节——比值大约 d/2 ≈ 32 FLOP/B（d=64）。A100 的 FP16 峰值 312 TFLOP/s 对 HBM 带宽 1.6 TB/s，盈亏平衡点约 195 FLOP/B。32 ≪ 195：算力在等数据，注意力是内存受限（memory-bound）的。这也解释了为什么大 GEMM 能跑满 80–90% 峰值，朴素注意力往往只有 30–40%。

FlashAttention 论文把这条账记成定理：标准注意力的 HBM 访问量是 Θ(Nd + N²)，而它做到 Θ(N²d²/M)（M 为 SRAM 容量）——d=64、M≈100 KB 时，分母带来约 25 倍的量级差。

softmax(S)·V，其中 S = QKᵀ/√d ∈ RN×N HBM 字节数（标准实现，前向，FP16）= 读 Q,K 4Nd ＋ S 写＋读 4N² ＋ P 写＋读 4N² ＋ 读 V、写 O 4Nd = 8N² ＋ 8Nd → 序列翻倍，流量翻两番；而 Q/K/V/O 本身只占 O(Nd)

③ MEMORY HIERARCHY / 快的小，慢的大

SRAM 快一个数量级，但每张显卡只有约 20 MB

A100-40GB · Ampere

GPU 不是一块均匀的记忆体。A100 有 108 个流式多处理器（SM），每个 SM 自带 192 KB 片上 SRAM，全卡合计约 20 MB、聚合带宽约 19 TB/s；而显存 HBM 有 40–80 GB，带宽只有 1.5–2.0 TB/s。容量差 3 个数量级，带宽差 1 个数量级——这就是全部优化空间的来源。

朴素注意力的每一步（QKᵀ、softmax、P·V）都把中间结果从 HBM 搬进搬出，等于一直在走慢车道。FlashAttention 的应对：既然整张 N×N 放不下，就把它切成能塞进 192 KB 的小块，每块在 SRAM 里算完就扔，永远不落盘。

点击下方层级查看参数；右侧拖动序列长度，看 N×N 矩阵比片上容量大出多少倍——差距越大，分块的收益越大。

④ TILING / 一个融合算子，跑完整个注意力

把 Q、K、V 切成块，让每张 S 小方块只活在 SRAM 里

演示：N = 16 · 块 = 4 · d = 4

FlashAttention 外层循环遍历 Q 的行块，内层循环扫过 K／V 的列块：每一步把一对小块从 HBM 读进 SRAM，在里面完成 Sij = QiKjᵀ、局部 softmax、乘上 Vj，累加进输出块 Oi，然后把 Sij 直接丢弃——它从未在 HBM 里存在过。

整个过程是一次 kernel 调用，而不是一串算子。打开因果掩码试试：下三角之外的块对根本不会被加载，这就是为什么因果注意力还能再省约一半流量。

按下播放，盯住两个计数器：「N×N 写入 HBM」恒为 0；总流量按块累计——读放大是存在的（每个 Q 块要把 K／V 重读一遍），这正是 IO 复杂度里那个 N²d²/M 的来源。

for i in 1..⌈N/Br⌉: 外层：每次一个 Q 块 for j in 1..⌈N/Bc⌉: 内层：扫过全部 K/V 块 Sij = QiKjᵀ/√d ← 在 SRAM 中 Oi ← Oi + softmax(Sij)·Vj ← 边算边并（见 ⑤） 块大小取 Bc = ⌈M/4d⌉，Br = min(⌈M/4d⌉, d)，保证三块同驻 SRAM

⑤ ONLINE SOFTMAX / 不看见整行，也能算出精确的 softmax

维护三个流动变量：m、ℓ、O，新块来了就 rescale

确定性数值 · 本地实时计算

分块带来一个数学难题：softmax 需要整行的最大值（数值稳定）和整行的指数和，但此刻 SRAM 里只有一块。解法是 2018 年就有的 online softmax（Milakov & Gimelshein）：边扫边维护三个量——目前见过的最大值 m、以 m 为基准的指数和 ℓ、未归一的输出累加器 O。

新块到来时，若它的局部最大值 mj 超过了 m，就把历史结果整体乘上修正因子 em−m新 再并入。这是精确的代数恒等变换，不是近似——最终结果与一次性 softmax 之差只有浮点舍入。

右侧是一个 8 个 key、分 2 块的真实数值演示。步进观察第二块里的 3.20 如何触发一次全局 rescale（α = e2.10−3.20 ≈ 0.333），而最终结果与直接计算逐位一致。

m新 = max(m, max(Sij)) 行最大值 · 每行一个 ℓ ← ℓ·em−m新 + Σ exp(Sij − m新) 指数和 · 历史先打折 O ← O·em−m新 + exp(Sij − m新)·Vj 输出累加器 · 同样打折再并入 收尾：O ← O/ℓ，并记下 L = m + ln ℓ（留给反向，见 ⑥）

⑥ RECOMPUTATION / 反向传播：重算一遍，比存下来更快

前向只留 O 和每行一个 L，反向在 SRAM 里重建 S 与 P

训练 · 前向 + 反向

训练需要反向传播，而反向需要用到 S 和 P。常规选择是把它们存下来——序列一长，显存立刻爆炸（这正是「FlashAttention 之前，长序列训练先 OOM」的原因）。FlashAttention 的选择近乎反常：什么都不存，反向时按同样的分块方式把 S、P 重算一遍。

前向只需额外保存每行一个数 L = m + ln ℓ（logsumexp），反向时 Q、K、V、O、dO 分块读入，借助 L 就地重建 Pij = exp(Sij − L)，算出梯度即弃。FLOPs 因此上升约 13%——但墙钟时间反而快得多：内存受限的世界里，多算比多存便宜。这也正是你在 KV Cache 里见过的那条 trade-off 的镜像：那一次用显存换计算，这一次用计算换显存。

前向保存：O [N,d] ＋ L [N] ← 显存 O(N·d)，与 N² 无关 反向重建：Pij = exp(QiKjᵀ/√d − L) ← 在 SRAM 中重算，用完即弃 对照：存 S＋P 需要 4N² 字节 / 头 / 层 · N=4096 时约 64 MiB，32 层 16 头 ≈ 32 GiB
