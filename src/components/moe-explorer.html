READING NOTES

看懂以后，记住这三件事。

MoE 不是把 token 拆成几块分给专家，也不是人工规定“语法专家”“数学专家”。路由分工从训练中得到，而且必须有负载均衡机制配合。

分派的是整个 token 表示

被选专家都读取同一份 x，各自独立执行完整 FFN。Top-k 表示复制到几路，不是把隐藏维切成 k 段。

专家权重来自路由概率

本原型对 Top-k 内的 Softmax 概率重新归一化；具体实现的归一化位置可能不同，应以模型定义为准。

推理省算力，不自动省显存

即使只激活少数专家，全部专家权重通常仍需可访问。多设备部署还会引入 dispatch／combine 通信。

“平均容量”不等于“实际负载”。

容量 C 按平均分支数再乘 Capacity Factor 得到。如果路由偏斜，某些专家会先装满；其他专家即使空闲，也不能保证原 Top-k 分支一定被保留。

TRAINING-ONLY MECHANISM

负载均衡损失，鼓励“别只用一个专家”。

下面的辅助损失采用 Switch 风格教学口径：f 是实际分派比例，P 是 Router 平均概率。它通过训练梯度改变未来路由，不是在推理时强行把 token 平均分配。

辅助损失怎样进入总损失？

fₑ = 专家 e 接受的分支数 / 全部分支请求数
Pₑ = 全批次对专家 e 的平均 Softmax 概率
L_aux = E · Σₑ fₑPₑ
L_total = L_task + α · L_aux

当前 L_task 固定为 1.840，仅用于观察系数 α 的作用。f 与 P 越一致地集中于同一专家，辅助损失通常越大；负载分散时更小。

注意：本沙盘不伪造“点击后训练完成”的效果，只计算当前批次的损失。真实训练需要反向传播更新 Router 与其他模型参数。

IMPLEMENTATION NOTES

容量算法不是唯一标准答案。

本原型使用透明、可复现的教学调度：按 token 顺序处理，先填原 Top-k；满员后尝试次优可用专家，无处可去才丢弃分支。

不同框架会不同

真实系统可能按路由优先级全局排序、使用不同 padding／drop 策略，或采用 dropless 与动态分组。这里展示一种具体规则，而非唯一标准。

丢弃的是专家分支

若某路被丢弃，剩余接受分支重新归一化；若全部丢弃，本原型的 MoE 分支输出为 0，token 仍可经残差主干继续传播。

省计算不等于无代价

专家并行还需要 dispatch／combine、批量整理与跨设备通信。路由均衡既关系模型质量，也关系硬件利用率。

WHAT THE ESTIMATE DOES NOT SAY

FLOPs 更低，不保证 wall-clock 更快。

本页是透明的数量级估算，不是某个真实模型的配置复现或延迟基准。它刻意把能精确写出的公式与需要实测的系统因素分开。

总显存看全部专家

稀疏激活减少每 token 计算，却通常不会减少需要存放的专家权重。量化只按相同字节数缩放本页估算，不包含 KV Cache、激活与运行时开销。

实际吞吐看批量与通信

小批量、专家负载不均、跨卡 All-to-All、padding 和 kernel 效率都可能抵消理论收益。多卡权重读取还会发生并行与复用。

“容量”不是“免费知识”

更多专家提供更大的条件参数容量，但能否形成有效分工取决于训练数据、Router、均衡目标和优化过程，不能仅由 E 推断模型质量。
